# LLM 时代如何更好地学习 Competitive Programming

## 核心原则

把 LLM 当成：

- 陪练
- 讲解器
- 代码审阅器
- 对拍与反例助手
- 题后复盘助手

不要把它当成“代打”。

如果你把 LLM 主要用来直接要题解、要 AC 代码、要完整证明，你得到的往往是短期效率，不是长期能力。

## 最推荐的 6 种用法

### 1. 让它帮你拆题，不要直接让它给答案

刚拿到一道题时，最好的问法不是“这题怎么做”，而是：

- 帮我提炼题意
- 帮我列出约束和关键边界
- 帮我判断目标复杂度
- 帮我列出 2 到 3 个可能方向，并比较为什么可行或不可行

这样你练到的是：

- 读题能力
- 建模能力
- 复杂度判断能力

而不是“看懂题解”的能力。

### 2. 卡题时只要下一层提示

如果你已经独立想了一段时间，不要立刻要完整解法。

更好的方式是分层提示：

1. 先提醒我该关注什么性质
2. 不要给完整解法，只给一个 hint
3. 如果我还不会，再给第二层 hint

这样更接近真实训练。

你真正需要练的是：

- 从模糊感觉走到明确思路
- 从思路走到可执行模型

而不是直接接收终答案。

### 3. 用它帮你做错因分析

很多时候你不是不会，而是不知道自己总错在哪一类。

做完题以后，把这些信息一起给 LLM：

- 你的思路
- 你的代码
- 评测现象：WA / TLE / MLE / RE
- 你怀疑的错误点

让它帮你分类：

- 是复杂度判断错了
- 是状态设计错了
- 是边界漏了
- 是实现不稳
- 是证明不充分

这比单纯看题解更有价值，因为它能帮你识别“自己的稳定薄弱点”。

### 4. 用它做对拍、造数据、找反例

这是 LLM 最实用的场景之一。

你可以让它帮你：

- 写一个暴力解
- 写随机数据生成器
- 专门构造边界数据
- 设计最容易卡掉当前思路的反例

这一类工作原本就偏机械，但价值很高。  
如果你把这一步固定下来，很多“思路对但实现错”的问题会更早暴露。

### 5. 用它做题目知识归档

每做完一道题，让 LLM 按固定模板帮你整理成一条笔记：

- 题型标签
- 关键性质
- 正解复杂度
- 为什么不是别的方法
- 最容易错的点
- 以后再见到什么题面特征要想到它

长期下来，你会积累自己的题型库。

这比单纯“刷过很多题”更重要，因为你在构建的是：

- 题目识别系统
- 方法选择系统
- 错误预警系统

### 6. 用它做二次讲解，而不是第一次替你想

最好的时机通常是：

- 你已经独立想了 $20$ 到 $40$ 分钟
- 你已经写下过自己的思路
- 你已经至少尝试过一版代码，或者能明确说出卡点

这时候再让 LLM 讲，它的价值最大。

因为此时它做的是：

- 帮你校正
- 帮你补缝
- 帮你抽象总结

而不是直接替代你的思考。

## 一个高效的训练流程

下面是一套很推荐的流程：

### 第 1 步：独立思考

给自己固定一个时间窗口，例如：

- 简单题：$20$ 到 $30$ 分钟
- 中档题：$30$ 到 $45$ 分钟

这段时间只做三件事：

- 读题
- 画样例
- 判断复杂度和可能方向

### 第 2 步：让 LLM 校验方向

此时不要问“给我题解”，而问：

- 我的复杂度判断对吗
- 这个方向为什么不行
- 在不直接给答案的前提下，提醒我该看哪个性质

### 第 3 步：自己写代码

哪怕思路已经比较明确，也要自己把代码敲出来。

因为你真正要练的是：

- 把思路落成实现
- 控制边界
- 写出稳定代码

### 第 4 步：让 LLM 帮你对拍和找反例

如果你怀疑实现有问题，优先让它帮你：

- 写暴力版本
- 设计随机测试
- 补极端边界

### 第 5 步：做题后复盘

最后再让它帮你总结：

- 这题最核心的性质是什么
- 我一开始为什么没想到
- 以后遇到什么特征要联想到这一类解法

## 最不推荐的 4 种用法

### 1. 直接贴题要完整题解

这会让你跳过最值钱的环节：

- 自己判断复杂度
- 自己试错
- 自己发现关键性质

### 2. 直接要 AC 代码

你会越来越像“看懂了”，而不是“会做了”。

比赛和训练中最容易出问题的，从来不是“看不懂代码”，而是：

- 自己写不出来
- 自己写出来不稳
- 自己遇到变形题不会迁移

### 3. 不自己思考就看答案

LLM 最危险的地方就在这里：

它太容易给你一种“我已经懂了”的错觉。

但 competitive programming 的能力本质上是：

- 题意抽象
- 性质识别
- 推导与构造
- 实现稳定性

这些能力都必须经过自己的主动思考。

### 4. 把“看懂了”当成“我会了”

真正的标准应该是：

- 你能自己复述思路
- 你能自己写出代码
- 你能自己说明复杂度
- 你能自己构造几个边界测试

达不到这几点，就不要轻易说“会了”。

## 一个建议的提问模板

下面这几个模板比较实用。

### 模板 1：拆题

```text
我在练一道算法题。先不要直接给题解。
请你只做这几件事：
1. 提炼题意
2. 列出关键约束
3. 判断目标复杂度大概在哪一档
4. 给我 2-3 个可能方向，并说明为什么可行或不可行
```

### 模板 2：分层提示

```text
我已经独立想了 30 分钟。
不要直接给完整解法，请先只给我第一层 hint。
如果我继续卡住，我再问你第二层 hint。
```

### 模板 3：错因分析

```text
这是我的思路、代码和评测结果。
不要直接重写答案。
请先帮我判断问题更像是：
1. 复杂度判断错
2. 状态设计错
3. 边界漏了
4. 实现错误
然后再指出最可能的两个具体错误点。
```

### 模板 4：对拍与反例

```text
这是我的解法。
请帮我：
1. 写一个暴力版本思路
2. 设计随机测试方向
3. 构造 5 类最容易卡掉这份代码的边界数据
```

### 模板 5：题后复盘

```text
请把这道题整理成复盘笔记，包含：
1. 题型标签
2. 关键性质
3. 正解复杂度
4. 为什么不是别的方法
5. 最容易错的点
6. 下次见到什么特征要想到它
```

## 最后一句建议

LLM 最好的角色不是“替你做题”，而是“让你的每次训练更完整”。

如果你能坚持这条顺序：

1. 先自己想
2. 再让 LLM 给提示
3. 自己写代码
4. 再让 LLM 做对拍、反例、复盘

那么 LLM 会显著提升你的训练效率。  
如果顺序反过来，它更可能削弱你的独立思考能力。
